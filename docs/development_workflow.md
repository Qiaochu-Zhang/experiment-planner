流程版本：1.0

当前状态：0.1 工程与可运行原型已建立；Ubuntu 核心/模型/存储/最小 Qt 测试已执行。完整软件功能、Windows 兼容性与离线运行尚未验收，实际证据见 [验收结果](acceptance_results.md)。

## 1. 文档用途与执行方式

本文把需求规格转换成可逐项实施、测试和检查的开发任务。功能含义以需求基线为准；本文不能缩减 F01–F25、R01–R09 或 A01–A50 的要求。

按阶段开发，每次完成一个能验证的小闭环，记录修改、测试结果、限制和下一步。遇到影响实验含义、目标平台或数据口径的问题再询问使用者。明确的技术路线及普通实现细节直接按规格推进，不逐项重复确认。

阶段完成必须有实际证据。代码存在、接口可调用、模拟案例通过、Windows 打包成功和正式离线验收是不同状态，分别记录。尚未执行的验证标为“未验证”，不能记为通过。

## 3. 全程必须保持的计算和数据规则

1. 初始模板保持规定的 8 个可控输入、4 项厚度测量和 3 个目标，不增设未经提供的机台约束。
2. A = SiO2初始厚度 − SiO2剩余厚度，B = SiN初始厚度 − SiN剩余厚度。完整保留正负号及原始测量。
3. 默认目标为最大化 abs(A)、最小化 abs(B)、最大化 abs(A/B)，采用 Pareto 方式。权重、归一化、阈值、参考点和目标变更均需版本化。
4. 首次含比值推荐前，要求用户明确选择分母策略。有效区域或稳定化策略必须配置有单位的 epsilon；移除比值目标也需明确保存。未配置时仍允许记录、计算差值及分别预测 A、B。
5. 缺失、False、失败、零值和比值不稳定分别保存。比值无效不能导致有效 A、B 丢失，也不能用零补缺失。
6. 区分字段来源、辅助记录、模型输入、模型响应和优化目标。未来事后测量不能作为推荐时已知输入。
7. 公式使用白名单解析与依赖图校验，不执行模板内任意 Python。检查字段、单位、循环依赖和非法运算。
8. 不确定度保留含义、分布假设和相关性。未知误差不是零，标准差、SEM、方差及误差界限不能混用。
9. 从 A、B 的联合样本计算非线性目标；共享来源只使用同一组样本。原始比值的有限样本统计不代表其均值或方差存在。
10. 执行精度、显示精度、建模取整和整齐数值偏好分开配置。采用一致的十进制半数远离零规则，最终执行值需重新校验和评分。
11. n 是本轮全部新增实验的总数，包含复测和对照。候选不足说明原因，不放宽限制或补造条件。
12. 先验必须实际进入支持的模型；不支持的组合明确阻止，不能把备注或软关系显示为严格约束。
13. 修改数据或配置使有关派生结果与模型缓存失效。旧推荐及其预测保留，旧任务不能覆盖新数据版本。
14. 模拟验证与公司内真实实验效果验证分开。真实实验数据不上传 AWS、GitHub 或云端开发工具。

## 4. 阶段顺序和进入条件

沿用需求的 M0–M6 编号。M0 的基础 Windows 依赖与最小打包验证优先；其涉及的新模型、先验、单/双变量完整检查，在对应模块实现后补齐。这样既尽早发现平台问题，也不把尚未开发的能力当作 M0 已通过。

Windows 条件未具备时，可先做平台无关的数据与计算核心，但 M0 保持未通过；大规模界面开发前必须完成基础 Windows 原型验证。完整离线发布必须通过全部适用阶段和验收。

### P0：需求整理与工程准备

任务：

- 保留现有规格作为需求基线，建立本流程和需求追踪表。
- 建立 Python 包结构、测试目录、开发说明和版本记录。
- 配置忽略规则，排除虚拟环境、缓存、构建产物和本地实验数据库。
- 核实当前环境与依赖；仅记录实际检查结果。
- 建立模拟数据目录，明确标识数据为合成案例。
- 后续如整理到 `docs/project_spec.md`，保持单一权威规格来源，避免两份全文独立修改。

交付：工程骨架、可运行的测试入口、环境检查记录、需求追踪表。

完成条件：能在当前开发环境执行测试入口；项目文档与实现状态一致。

### M0：跨平台与模型接口原型

任务：

1. 确认目标 Windows 版本和可用构建机。
2. 在干净 Windows Python 环境安装候选 CPU 依赖，分别记录 Linux 与 Windows 的解析结果及完整依赖来源。
3. 使用模拟数据跑通 Ax 建实验、初始化、真实 GP 拟合推荐、回填、保存与恢复。
4. 验证基础响应联合采样、非线性多目标及分母策略的接口；优先验证规格要求的 qLogNEHVI / qLogNEI 路线。
5. 验证最小 PySide6 窗口、表格和带不确定度的本地图形。
6. 在 Windows 构建最小目录包，在未安装 Python 的 Windows 测试机启动。
7. 随 M1–M2c 补验非 GP、布尔、先验、精度和单/双变量循环，记录扩展适配结论。

交付：可复现原型脚本、平台依赖记录、打包配置、Windows 测试报告及失败修复记录。

完成条件：需求第 11.3 节的最小验证有实际执行证据；初始化与 GP 推荐可区分；恢复前后业务记录一致。Ubuntu 测试不能替代 Windows 结果。

### M1：模板、字段、公式与精度

实施顺序：

1. 实现 schema v2、字段类型和独立角色；支持数值、离散、类别、固定值、布尔、备注。
2. 实现初始 ICP JSON 模板、校验、复制、版本化及项目快照。
3. 实现白名单公式、依赖排序、单位检查和明确的缺失/非法状态。
4. 实现 A、B、原始比值和分母策略配置；保留计算来源与公式版本。
5. 实现十进制取整、网格起点及精度冲突校验，分离原值、变换值与显示值。
6. 实现防止事后输入泄漏的角色与依赖检查。

交付：domain、metrics、precision 模块，内置模板及核心测试。

完成条件：4 项厚度正确得到有符号 A、B；零分母不产生可供训练的 NaN/Infinity；非法公式被拒绝；False 与缺失独立；显示舍入不改变原始比值。

主要验收：A25–A29、A33–A35、A39–A40、A44–A45；模板持久化项由 M3 补齐。

### M2a：测量不确定度

实施顺序：

1. 保存标准不确定度、SEM、区间/覆盖因子、误差界限、非对称误差及未知含义。
2. 实现差值传播、协方差和共享来源；相关性未提供时显式记录独立假设。
3. 对非线性公式选择适用的蒙特卡洛或区间方法，保留算法与随机设置。
4. 处理分母区间跨零和低于分辨能力的状态，不强制生成原始比值均值/标准差。
5. 定义送往模型的观测噪声接口，区分潜在响应区间与未来测量区间。
6. 对未支持的输入位置误差或相关观测组合明确报能力限制。

交付：误差数据对象、传播模块、手算与模拟对照测试、模型噪声接口说明。

完成条件：100±1 与 90±1 的独立 1σ 差值为 10±sqrt(2) nm；误差界限得到相应界限；95% 区间按明确假设换算；共享误差不会重复独立抽样。

主要验收：A28、A30–A32、A47、A49。

### M2b：模型、联合预测与关系先验

实施顺序：

1. 建立模型预设注册表和能力表，记录模型、特征、噪声、采样及版本。
2. 接入 GP-RBF 和 GP-Matérn 2.5，针对有效的有符号基础响应拟合。
3. 实现贝叶斯线性回归的 BoTorch 适配，保留候选间联合不确定性。
4. 实现明确 Bernoulli 似然及推断方案的布尔响应模型，验证单类别/少数据状态。
5. 实现按响应排除无关输入、正比/线性软先验及单调软信息；保存范围、强度、来源和版本。
6. 从同一基础后验样本得到派生目标，保存跨输出独立等实际假设。
7. 实现不支持组合的能力检查、模型切换和缓存失效。

交付：engine、knowledge 模块，能力矩阵，预测接口和模拟验证报告。

完成条件：三个数值预设真实拟合且可切换；布尔结果是合法概率；先验在可复现案例中实际影响模型；对 A 排除某输入不影响 B 的输入集合；非线性预测与联合样本一致。

主要验收：A17–A18、A36–A38、A46–A47、A49–A50。

### M2c：受限推荐、配额与对照

实施顺序：

1. 统一输入合法性检查，覆盖范围、网格、固定值、类别及已支持组合/线性约束。
2. 构建全范围、指定基准单变量、最多/恰好双变量和指定变量子空间。
3. 接入 Pareto、单目标加约束、明确权重与归一化方案；保存参考点和目标配置。
4. 在采集函数中落实分母策略、输出约束和待做条件处理。
5. 实现复测及基准/单 A/单 B/AB 交叉布局配额，统一计入 n。
6. 对最终执行值校验、去重、预测和评分，再输出变化明细及不足额原因。
7. 为用户选择的趋势图保存同一模型版本与最终条件配置。

交付：推荐业务服务、批次结果结构、受限初始化和数据驱动推荐测试。

完成条件：每点的原始参数变化数量正确；冻结项不变；不超总配额；不足额不放宽条件；待做点不被无意重复；初始化不显示伪造预测。

主要验收：A07–A12、A28–A29、A41–A43。

### M3：持久化、导入导出、修订与恢复

存储的数据结构在 M1 起同步设计，最小保存闭环可提前实现；本阶段完成整套一致性与恢复验收。

实施顺序：

1. 建立项目、实验、原始观测、派生值、先验、误差来源、批次、预测/引擎快照和变更日志。
2. 实现项目新建、打开、关闭及模板快照隔离。
3. 保存建议与实际条件、部分结果、失败/取消状态和逐字段备注。
4. 实现 CSV/XLSX 映射预览、单位/类型/误差检查、重复导入识别及确认后提交。
5. 实现更正追踪、依赖重算、数据版本递增和模型缓存失效。
6. 后台计算在写事务外运行；整批提交前检查版本，原子保存。
7. 使用 SQLite 一致性备份，验证重启、恢复、迁移前备份与回退。
8. Ax 快照不兼容时从有效业务记录重建；不得将读取失败变成空项目。

交付：storage、application、io 模块，迁移脚本与集成测试。

完成条件：两项目独立；重复导入不重复训练；更正保留原值；旧计算结果不覆盖新数据；重启保留待做批次；备份恢复内容一致。

主要验收：A02–A06、A11、A13–A16、A19–A20、A24、A44–A45。

### M4：中文桌面界面与趋势分析

页面按完整操作流程逐步接入：

1. 项目主页、模板与字段。
2. 公式与目标、先验与误差。
3. 实验记录与导入预览。
4. 下一批实验、模型选择、配额及变化限制。
5. 分析与预测，包括一维曲线、二维响应面、基准对照、Pareto 与进展图。
6. 设置、备份、完整精度导出和本地帮助。

界面只通过业务服务读写。后台任务处理 Windows spawn、取消、崩溃及重复点击；每项目同一时间只允许一个生成任务。

交付：ui、worker、plots 模块，关键界面测试及中文使用说明。

完成条件：非编程人员可以用模拟数据完成建项目→录入/导入→推荐→回填→重启恢复；图形标明固定条件、单位、预测/实测与区间含义；取消任务不损坏项目。

主要验收：A02、A05、A16、A18–A19、A23、A48–A49。

### M5：Windows 离线发布

任务：

- 在 Windows 固定已验证依赖，构建包含模型、Qt、图形和资源的目录包。

- 在干净且未安装 Python 的 Windows 电脑断网执行完整模拟流程。
- 在联网测试机配置出站阻断并监测主程序和计算子进程，记录结果。
- 验证跨机备份恢复、离线升级、失败回退及无缓存运行。
- 提供使用说明、部署说明、版本/依赖/许可证清单、SHA-256 校验值及发布记录。

完成条件：A01–A50 中适用于正式软件的功能项全部有通过证据；无未解决的阻断问题；发布包不含开发凭据、真实数据库或自动联网逻辑。

主要验收：A01、A19–A24、A50，并回归其余验收项。

### M6：公司内小规模试用

任务：由实验人员在公司本地使用真实数据验证流程、测量误差口径和模型假设，记录建议可执行性与实际优化效果。

问题反馈优先使用错误描述及可复现模拟案例。真实数据和模型快照留在公司环境。

完成条件：场景负责人确认可用，记录限制与后续调整；不以一次模拟最好成绩替代真实效果评价。

## 6. 每个开发小步的工作流程

1. 从当前阶段选一个有明确输入、输出和验收条件的任务。
2. 对照需求确定语义；涉及用户实验含义的不确定问题先问，其他独立工作继续。
3. 检查相关代码与依赖接口，实施模块和必要的错误处理。
4. 对计算、约束、持久化等关键逻辑编写有实际判定价值的测试；普通文档修改直接核对。
5. 运行相关检查，记录命令、平台和结果；有失败先修复，不将未执行项目勾为完成。
6. 更新功能追踪、阶段状态、使用说明及重要设计决定。
7. 向使用者说明已完成内容、验证结果、剩余限制和下一步。

Git 提交与同步按当前授权执行。同步前检查文件清单，虚拟环境和本地实验数据不加入源码；不会因文档中写了发布流程就自动进行外部发布。
