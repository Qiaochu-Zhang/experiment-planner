## 3. 修复的确定性缺陷

### 3.1 有效区域策略错误显示原始比值

原来 `Objectives.values()` 同时服务优化和显示。在 `valid_region` 下把 `abs(A/B)` 替换为 `abs(A)/max(abs(B), epsilon)` 后，预测汇总仍以原始比值字段输出截断分位数；`objective_predictions` 也有同样问题。

独立样本为 `(A,B)=(-4,0.1),(2,-0.2),(6,2),(-8,-4)`，epsilon=1 nm。原始比值为 40、10、3、2，中位数 6.5；旧代码输出 2.5，97.5% 分位数输出 3.925 而正确值为 37.75。

修复：区分公式原始值和优化用值。显示原始比值及其目标分位数时使用原始样本，稳定化指标另算另存。有效区域的采集函数仍用有限分母保护及原有可行性约束，四个样本的可行概率仍为 0.5；不会把不可行样本丢弃后冒充全体后验。原始比值均值继续为 `None`。

注意：旧批次保存在数据库中的历史预测不会自动改写；如要使用更正后的值，需要重新预测，并保留旧版本用于追溯。

### 3.2 预测公式缺少长度单位换算

实测公式解释器以 nm 作为标准长度单位，预测用张量解释器原来直接对字段数值计算。例：`1000 nm − 0.5 um`，实测得到 500 nm，预测错误得到 999.5 nm。

修复：预测读取 `um` 字段时乘 1000；输出 `um` 指标时除以 1000。新增测试同时验证 nm 与 um 的混合计算、输出换算、以及下一层公式重新读取 um 的链式换算。默认 ICP 模板全部为 nm，其线性拟合过程不变。

## 4. 实际验证命令

在 `python-version` 中执行，Linux GUI 使用离屏模式：

```bash
QT_QPA_PLATFORM=offscreen ../.venv/bin/python -m pytest -q \
  --junitxml=docs/evidence/prediction-audit-2026-09-20/baseline-tests.xml

# 增加测试但尚未修复实现时执行，预期记录两个失败：
QT_QPA_PLATFORM=offscreen ../.venv/bin/python -m pytest -q \
  tests/integration/test_prediction_validity.py \
  --junitxml=docs/evidence/prediction-audit-2026-09-20/defects-before-fix.xml

# 修复后执行同一新增测试，JUnit 改存 defects-after-fix.xml。

../.venv/bin/python scripts/validate_prediction.py \
  --output docs/evidence/prediction-audit-2026-09-20/benchmark.json

QT_QPA_PLATFORM=offscreen ../.venv/bin/python -m pytest -q \
  --junitxml=docs/evidence/prediction-audit-2026-09-20/final-tests.xml
```

执行时用 `set -o pipefail` 和 `tee` 保存对应 `.txt`，失败退出码不会被日志管道掩盖。上述为当次命令；再次执行请使用新证据目录，尤其评估脚本会拒绝覆盖已有 JSON。独立 Python 环境可把 `../.venv/bin/python` 换成自己的 `python`。

初次只读命令因执行环境的 `bwrap` 回环网络权限失败，随后使用获准的执行环境运行检查；这是环境启动问题，不是应用测试失败。后续一个更新补丁遇到同样的沙箱读取问题，改用带精确旧文本断言的本地脚本完成同一修改，没有因此扩大文件范围。
