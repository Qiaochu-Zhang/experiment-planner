**关于模型预测、先验、实验目标、重复数据、取整和探索策略的回答**

本文依据 `python-version` 当前源码、内置 ICP 模板及相关测试逐项核对。核对日期：2026-09-29；代码基线：`63dd4a5`。以下描述的是已经实现的行为。本文只新增说明文件，没有修改原有代码、模板或实验数据。

**1. 模型预测结果是怎么得到的？为什么需要抽样？**

程序先用已有实验学习“输入条件和刻蚀结果的关系”，再对指定的新条件给出可能结果的分布，最后从这个分布计算均值、区间和目标指标。

以内置 ICP 模板为例，计算顺序如下：

1. 读取状态为“完成”或“部分结果”的记录。对每一个基础响应，分别筛选有有效结果的记录；待做、进行中、失败、取消的记录不作为已测响应训练。
2. 根据原始厚度计算两个**带正负号**的基础响应：`A = SiO2 初始厚度 − SiO2 剩余厚度`，`B = SiN 初始厚度 − SiN 剩余厚度`。
3. 用八个工艺输入——Cl2、BCl3、Ar、ICP、RF、压力、温度、刻蚀时间——分别拟合 A、B 的模型。数值输入按模板范围缩放；初始厚度参与计算 A、B，但默认不作为预测输入。
4. 对新条件计算 A、B 的后验分布，也就是“在已有数据和模型假设下，哪些结果比较可能”。然后用同一组抽样结果计算 `abs(A)`、`abs(B)`、`abs(A/B)` 等非线性指标。
5. 输出基础响应的样本均值，以及 2.5%、50%、97.5% 分位数；原始比值只报告样本分位数，`mean` 留为 `null`。

默认模型是 **GP / RBF 高斯过程**：利用输入条件之间的相似程度学习响应规律，同时估计不确定性。界面还可选择 GP / Matérn 2.5 或贝叶斯线性回归。已提供且可转换的测量标准不确定度会以方差 `u²` 进入拟合；全部未提供时，GP 估计未知噪声，线性模型采用明确的经验残差估计。同一个响应混合“已知噪声”和“未知噪声”目前会报能力限制。

**这里的预测抽样不是从历史记录中随机抽走一部分来训练，也不意味着要再做几百次真实实验。** 当前拟合会使用该基础响应的全部有效记录。抽样发生在拟合之后：从模型给出的可能结果分布中，在计算机里生成许多组 `(A, B)`。

之所以这样做，是因为“先取平均，再做非线性运算”通常不等于“先运算，再取平均”。例如，假设一个结果等概率为 −10 和 +10，则平均结果为 0，但绝对值的平均为 10。只计算 `abs(预测均值)` 就会得到错误的 0。同样，`abs(A 的均值 / B 的均值)` 不能代替比值的预测统计，尤其当 B 可能接近零时。

每一组 `(A, B)` 都先计算一次绝对值和比值，再汇总这些结果，才能把模型不确定性传到派生目标。满足输出约束的样本比例用于估计 `feasibility_probability`；它表示可行概率，不是预测准确率。高斯模型的基础响应本身可有解析均值和方差，本项目选择共同抽样流程，是为了统一处理非线性目标、约束和推荐评分。

代码中有几种不同用途的“抽样”，不要混为一谈：

| 用途 | 当前数量或默认值 | 含义 |
| --- | --- | --- |
| 展示预测结果 | `prediction_summary(..., samples=512)` | 每组条件从后验抽样 512 次，用来汇总预测统计。 |
| 推荐评分 | 采集函数使用 32 个样本 | 估计候选条件带来改善的程度，服务于下一批实验选择。 |
| 自动 Pareto 参考点 | 使用 64 个后验样本 | 估计历史条件的有向目标均值；未手动配置参考点时据此生成参考点。 |
| 原始测量的不确定度传播 | `propagate(..., samples=4096)` | 将已录入的测量误差传到派生公式；ICP 的两项差值随后使用精确差值传播结果。 |
| 搜索候选条件 | `pool_size=128` | 建立最多 128 个合法候选条件的候选池，供推荐评分；这是输入条件采样，不是结果分布抽样。 |

这些数字不表示训练轮数或真实实验次数。当前界面没有预测抽样数量输入框；`prediction_summary` 的 `samples` 可通过直接 Python 调用调整，但普通预测 JSON 入口没有接入这个设置，往请求中加 `samples` 不会改变抽样次数。采集函数样本数目前写在推荐代码中。`pool_size` 则可通过批次 JSON / Python 接口设置。

当前 A、B 使用条件独立的基础响应模型，未学习跨响应协方差；同一个响应在不同预测条件之间的相关性仍保留。输出的区间标为 `latent_response`，表示潜在响应的不确定性，没有自动叠加未来一次量测的额外噪声。

每个基础响应至少需要两条有效记录才进入模型推荐阶段；不足时推荐入口返回初始化条件、不提供预测，独立预测入口则提示数据不足。两条只是程序启动门槛，不代表数据量已经足以准确预测八维工艺空间。

依据：[模型拟合 `fit_models`](src/experiment_planner/engine/models.py)、[预测汇总 `prediction_summary`](src/experiment_planner/engine/objectives.py)、[推荐 `generate`](src/experiment_planner/engine/planner.py)、[不确定度传播](src/experiment_planner/metrics/uncertainty.py)、[记录派生值处理](src/experiment_planner/application/records.py)。

**2. 模型先验关系是在模板中定义的吗？在哪里改？**

**用户提供的工艺关系先验在项目模板的 `knowledge_priors` 中定义。内置模板的这一项是空列表 `[]`，没有预先写入“某种气体一定增加刻蚀量”等具体物理规律。**

但空列表不等于模型完全没有假设。GP 的核函数、噪声处理、线性模型的系数先验等由模型实现决定；基础响应之间采用独立模型也是当前实现的假设。这些和用户添加的工艺经验是两个层次。

界面修改入口：打开项目 → **“模板 / 公式 / 先验” → “编辑项目模板”** → 编辑 `knowledge_priors` → 保存。保存会自动递增模板版本。

例如，下列是配置结构示例，系数和强度仅用于说明，不能当作真实机台结论直接采用：

```json
"knowledge_priors": [
  {
    "input": "etch_time_s",
    "response": "sio2_loss_nm",
    "relation": "linear",
    "coefficient": 0.2,
    "strength": 1.0,
    "source": "示例；实际使用时填写实验或文献依据",
    "enabled": true
  }
]
```

这里 `coefficient: 0.2` 表示先验估计“刻蚀时间每增加 1 s，SiO2 刻蚀量增加约 0.2 nm”；`strength` 控制先验作用强度，不是百分比置信度。

| 关系字段 `relation` | 当前实际作用 |
| --- | --- |
| `independent` | 对指定响应移除这个输入特征，表示模型不使用它；不等于把该工艺输入固定。 |
| `linear` / `proportional` | 在线性模型中设置系数先验；在 GP 中加入软线性趋势并拟合残差。不会保证实际结果严格线性或严格过原点。 |
| `monotonic` / `weak` | 目前仅贝叶斯线性模型支持，以系数先验表达方向或弱影响；不是全域严格形状约束。 |

当前先验只能连接可控输入和基础响应；非无关关系的系数先验要求数值输入。严格比例、非空局部 `range` 和跨响应相关噪声等组合尚未接入，不能靠写入模板就启用。普通备注不会自动成为先验。

模板中的 `context_assumptions` 还记录了“初始厚度不作为刻蚀量模型输入”的场景假设。这是说明性记录，实际角色由字段配置控制；当前引擎尚不支持额外实验前测量或派生字段作为模型输入，不能只把初始厚度的 `use_as_model_input` 改成 `true` 就完成这一扩展。

依据：[内置 ICP 模板](src/experiment_planner/resources/templates/icp.json)、[先验能力检查](src/experiment_planner/knowledge/priors.py)、[先验进入拟合的位置](src/experiment_planner/engine/models.py)。

**3. 原来的实验目标是什么？有没有绝对值？在哪里改？**

**有绝对值。原项目说明和当前内置模板一致，默认采用三目标 Pareto 优化：**

| 目标 | 数学含义 | 模板位置 |
| --- | --- | --- |
| SiO2 刻蚀量绝对值尽量大 | 最大化 `abs(A)` | `objectives` 中 `metric: "sio2_loss_nm"`，`transform: "abs"`，`direction: "maximize"`。 |
| SiN 刻蚀量接近零 | 最小化 `abs(B - 0)`，即 `abs(B)` | `metric: "sin_loss_nm"`，`transform: "absolute_distance"`，`target: 0`，`direction: "minimize"`。 |
| 刻蚀量比值绝对值尽量大 | 最大化 `abs(A/B)` | `derived_metrics` 中先定义绝对值比值公式，`objectives` 对它使用 `identity`、`maximize`。 |

`A`、`B` 的原始差值都保留正负号。绝对值是在目标评价阶段使用的。因此，第一项目标会把 A = −20 和 A = +20 视为同样的目标值 20；第二项目标不会把 B 越负视为越好，而是看它离零多远。比值目标的 `transform: "identity"` 也不表示没有绝对值，因为绝对值已经在 `selectivity_abs` 的公式中。

“Pareto”表示同时寻找这些目标之间的折中，目前默认 `optimization.mode` 为 `pareto`，`weights` 为 `null`，没有默认的三目标加权比例。

已有项目的修改入口仍是 **“模板 / 公式 / 先验” → “编辑项目模板”**：

- 改优化哪个指标、方向或绝对值处理：修改 `objectives`。
- 改指标如何从原始测量计算：修改 `derived_metrics[].expression`。
- 改单目标、Pareto 或加权模式：修改 `optimization`。加权模式还需填写与实际参与目标对应的 `weights` 和正数 `scales`。
- 改零分母策略：可在“下一批实验”页设置，再点击“保存目标策略版本”；也可编辑模板中的 `ratio_policy`。

例如，如果实际意图是“SiO2 正向刻蚀量越大越好”，可将 A 对应目标的 `transform` 从 `abs` 改为 `identity`，保留 `maximize`。如果意图是“SiN 刻蚀量接近某个非零值”，可修改其 `target`，保留 `absolute_distance` 和 `minimize`。这些例子只是解释修改含义，本次没有实际修改目标。

比值目标默认要求先选择分母策略，未配置前推荐入口会阻止生成批次：

| 策略 | 实际优化含义 |
| --- | --- |
| `valid_region` | 用 `abs(B) ≥ epsilon_nm` 作为可行条件；采集函数内部也会保护小分母数值。与“B 尽量接近零”存在折中。 |
| `stabilized` | 优化 `abs(A) / max(abs(B), epsilon_nm)`，同时保留原始比值记录。 |
| `remove` | 移除比值优化目标，原始比值仍可记录、展示。 |

`epsilon_nm` 是按测量口径选择的正数阈值，不是探索比例。

**已有项目使用保存在 `.sqlite` 中的模板快照。** 修改安装目录中的 `icp.json` 不会自动更新已有项目；应通过上述项目模板编辑入口保存。该入口会重算派生值，后续预测再按新模板拟合，旧批次预测仍保留。命令行更新模板需自行递增 `template_version`。字段名、类型、单位、范围等结构变更目前要求导出模板后“从模板新建”项目。

依据：[原项目说明第 2 节](docs/project_spec.md)、[内置模板](src/experiment_planner/resources/templates/icp.json)、[目标变换实现](src/experiment_planner/engine/objectives.py)、[模板编辑入口](src/experiment_planner/ui/desktop.py)、[模板更新与重算](src/experiment_planner/application/service.py)。

**4. 重复数据怎么处理？是否不允许相同实验点得到不同结果？**

**允许同一组工艺条件得到不同测量结果；不同次真实实验应分别保存成不同实验记录。** 当前代码区分“重复做实验”和“把同一条记录重复导入”。

| 情况 | 当前处理 |
| --- | --- |
| 手动新增两条条件相同、结果不同的记录 | 允许；各自保留实验编号、测量结果和备注。 |
| CSV / Excel 中条件相同，但不同次实验使用不同 `external_id` | 允许；即使结果碰巧也相同，仍是两次独立实验。 |
| 相同 `external_id`，内容也相同，再次导入 | 跳过，不再新增。 |
| 相同 `external_id`，但测量结果等内容不同 | 报“同一外部实验编号内容冲突”；若是更正同一次实验，应使用更正功能，若是另一次复测，应换用该次实验自己的唯一编号。 |
| 没有外部编号 | 按待导入记录内容的哈希去重。完全相同的内容会跳过；结果不同则可作为不同记录导入。 |
| 自动推荐一般新条件 | 排除全部历史记录中已有的实际条件，也排除本批次已选条件。此处用于避免自动重复安排，不会删除历史复测数据。 |
| 明确指定复测 | 通过“复测实验编号”或 `repeat_ids` 安排旧条件再做一次，允许条件重复。 |

CSV / Excel 推荐给**每一次实际实验**填写唯一 `external_id`，例如 `run-001`、`run-002`。不应把同一配方的所有实验都填成同一个编号。导入器也识别 `experiment_id`，但如果同时填写，优先采用 `external_id`。

界面操作示例：本轮 `n=6`，复测实验编号填 `3,8`，程序会先安排这两条旧条件复测，占两个名额；普通推荐模式下，剩余最多四个名额用于新条件。复测来源记录须处于“完成”或“部分结果”状态，条件也须符合当前模板。实际完成后，应在**新生成的待做复测记录**上回填结果，不要覆盖原来的第 3、8 条实验。

拟合时，同条件的有效记录会逐条进入训练数据，没有先按工艺条件删除重复行或自动合并成平均值。有已知误差时使用各条误差；未知误差按对应模型的噪声机制处理。因此，同一输入下不同结果可以反映观测波动。若重复记录存在跨实验共享误差来源，当前相关噪声模型尚未支持，会报能力限制，不能直接当作独立误差处理。

自动“新条件”的历史去重比较的是完整实际输入组合，不看结果是否相同，并且当前连失败、取消的历史条件也会排除。若需要重做这些条件，可以手动新增记录；`repeat_ids` 本身只接受完成或部分结果记录。

交叉布局另有规则：交叉组可以与已完成历史条件重合，但与已有待做、进行中条件重合时会阻止生成，要求先处理原计划。额外指定的复测与交叉基准组不会自动合并。

此前出现的 `Arm already exists with name experiment_...` 属于 Ax 对同条件配方命名的冲突。当前代码已修复：相同条件共享 Ax 配方名，每一次实际实验保留自己的 trial 和数据。因此，不需要为了避开旧报错而篡改工艺条件或删除真实复测结果。

依据：[导入与记录服务](src/experiment_planner/application/service.py)、[导入编号解析](src/experiment_planner/io/exchange.py)、[推荐与复测](src/experiment_planner/engine/planner.py)、[候选池去重](src/experiment_planner/engine/space.py)、[Ax 重复条件处理](src/experiment_planner/engine/ax_bridge.py)、[重复条件回归测试](tests/integration/test_ax_bridge.py)。

**5. 数据取整数是在模板里改 `digit` 吗？**

**字段名是 `digits`，但要先区分“只显示整数”和“设备执行条件必须是整数”。** 两者配置不同，也都不等于把历史测量或模型结果改成整数。

| 需求 | 配置 | 实际影响 |
| --- | --- | --- |
| 界面表格只显示整数 | 对应字段的 `display_digits: 0` | 只改变显示；原始值、计算、训练和导出仍保留原精度。 |
| 推荐的工艺条件只能取整数 | 对应参数的 `execution_rounding` 设置 `mode: "digits"`、`digits: 0` | 限制推荐和预测条件的合法取值网格；默认网格起点为 0。 |
| 工艺条件按 5、10 等步长取值 | `mode: "step"`，设置 `step`，`digits` 留为 `null` | 例如 `step: 5`、默认起点 0 时，允许 0、5、10……，还要满足参数范围和其他约束。 |
| 字段从数据类型上就必须是整数 | `value_type: "int"` | 非整数输入会被拒绝，不会自动四舍五入；已有项目改字段类型需新建项目。 |
| 建模前把数据整体取整 | 不能只改一个 `digits` 来实现 | `modeling_rounding` 当前未接入，启用会报能力限制。 |

例如，在某个工艺参数对象中配置下面这些字段，可让它的建议执行值落在整数网格上，并在表格中显示为整数；其余字段保持原值：

```json
"execution_rounding": {
  "mode": "digits",
  "digits": 0,
  "step": null,
  "origin": 0
},
"display_digits": 0
```

不能只把 `digits` 改成 0，却仍保留 `mode: "none"`；当前校验会报错。`digits: 1` 对应 0.1 网格，`digits: -1` 对应 10 的网格。若同时填写 `digits` 和 `step`，它们必须一致。

执行网格是对新建议和预测条件的要求，输入不在网格上时可能被拒绝，并非所有入口都会自动取整。对于仍为 `float` 类型的参数，历史导入和实际回填允许保留设备实际执行偏差，例如建议 20、实际 20.3；不会为了整数建议网格把实测 20.3 覆盖成 20。厚度等原始测量也不会因为工艺参数设置整数网格而被取整。

此外，输入条件是整数并不意味着预测的刻蚀量也是整数；模型仍可预测 10.6 nm。`display_digits` 主要用于记录表格格式化，预测页面的 JSON 输出并不会因此整体取整。

依据：[取整与显示实现](src/experiment_planner/precision/rounding.py)、[字段类型和条件校验](src/experiment_planner/domain/template.py)、[实际记录保留执行偏差](src/experiment_planner/application/service.py)、[记录表格显示](src/experiment_planner/ui/window.py)。

**6. 目前策略是一部分探索、一部分优化吗？两者比例是多少？能改吗？**

**当前没有“固定 X% 探索、Y% 优化”的分配规则，也没有可直接设置的探索比例参数。** 它分为初始化和模型驱动两个阶段；模型驱动阶段用同一个推荐评分兼顾改善潜力和不确定性。

| 阶段 / 安排方式 | 当前选择方式 |
| --- | --- |
| 数据不足：`initialization` | 任一基础响应少于两条有效记录时，从合法候选池中给出初始化条件，不使用模型预测评分。 |
| 数据足够：`model_driven`，普通新条件 | 拟合模型，为候选条件计算采集函数评分，逐个选择最高分者；每选一个就将其加入待做集合，再评价后续候选。 |
| 用户指定复测或交叉布局 | 按用户指定的安排生成，不是按某个探索百分比自动分配；数据足够时也会给这些条件附上模型预测。 |

默认 Pareto 模式使用 `qLogNoisyExpectedHypervolumeImprovement`：根据可能结果，衡量候选条件对现有多目标折中的预期改善。单目标或显式加权模式使用 `qLogNoisyExpectedImprovement`。二者都会利用后验分布，而不只看预测均值。

通俗地说，一个条件可能因为“模型认为结果较好”被选中，也可能因为“不确定性较大，但有机会取得更大改善”被选中。这就是推荐评分中的探索与利用权衡；高不确定性本身并不保证被选中。代码没有给每个点贴上“纯探索”或“纯优化”标签，所以不能把当前批次准确报成固定的 30% / 70% 或 50% / 50%。

候选池里会使用随机采样和打乱，但模型阶段的普通新条件仍按采集函数评分选出；不能把“候选池是随机产生的”理解成“最终实验有固定一部分随机探索”。界面的“全范围探索”也只是允许在整个模板范围搜索，并不代表关闭优化或只随机选点。

目前可以改的设置包括：

- **本轮数量和复测安排**：`n`、`repeat_ids`。例如六个名额安排两次复测，表示复测占 2/6；这不是探索占 2/6。
- **搜索范围和允许变化的变量**：全范围、单变量、双变量、交叉布局，以及基准和 `variables`。它们限制在哪些条件里选点，不设置探索比例。
- **模型、目标、约束及比值策略**：会影响后验分布或推荐评分。`optimization.weights` 表示各实验目标的重要程度，也不是探索/优化权重。
- **候选池大小与随机种子**：通过批次 JSON / Python 接口设置 `pool_size`、`seed`。默认候选池上限为 128，合法配置范围为 1–10000。增加它只会扩大供评分的候选池，并可能增加计算耗时，不会直接提高某个“探索百分比”。

如果希望明确要求“每批六个实验中，两个专门探索、四个用于优化”，**需要新增策略代码和相应配置入口**：先明确探索点是随机覆盖还是按不确定性选择，再按配额选择并统一处理约束、去重、复测和待做条件。主要改动位置会是 `engine/planner.py`、`engine/space.py` 及界面/请求入口。当前不能只往模板添加一个 `exploration_ratio` 就生效；`batch_defaults` 也不是已接入的探索比例开关。本次按要求仅作说明，没有实现这种新策略。
