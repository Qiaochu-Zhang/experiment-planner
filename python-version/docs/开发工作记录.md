## 十、重复条件导致 Arm 名称冲突的修复

日期：2026-09-21。范围：Python 源码版。

用户在计算时遇到 `Arm already exists with name experiment_2, which doesn't match given arm name of experiment_3.`。使用临时合成项目复现了完全相同的错误：实验 2、3 的实际条件相同，测量结果可以不同。

原因是 Ax 将一组参数条件视为一个 Arm，同一组条件需要使用相同名称；旧版却按每条业务实验编号强制命名。当存在复测、交叉布局中的基准复测或同条件历史记录时，下一次重建 Ax 实验就会产生冲突。把重复记录改成取消也无法修复旧版命名问题，因为重建包含所有状态的记录。

本轮修改：

- [ax_bridge.py](../src/experiment_planner/engine/ax_bridge.py)：首次遇到条件时保留原有命名方式，再次遇到相同条件时让 Ax 复用已有名称。每条业务实验仍有独立 trial、编号映射、状态和测量行；不会把不同次实测取平均或丢弃。
- [test_ax_bridge.py](../tests/integration/test_ax_bridge.py)：增加 8 项回归用例，覆盖完成、部分结果、待做、进行中、失败、取消的重复条件；另验证复测／交叉基准复测保存后再次推荐，回填后保留旧预测、两次有效测量都参与训练，以及备份恢复后的继续推荐。
- [参数与操作白话说明](../参数与操作白话说明.md)：补充该报错的含义和更新方式。

实际验证：修复前运行新增测试，8 项均因 Arm 名称冲突失败；修复后运行完整测试，**87 项通过，耗时 34.02 秒**。执行命令：

```bash
PYTHONPATH=src ../.venv/bin/python -m pytest -q
```

测试产生 3 条依赖弃用提示和 6 条模型矩阵数值稳定化提示，没有失败。测试使用临时合成数据库；未读取或修改用户机台的实际数据库。本轮未进行 Windows 实机操作验证。

使用已有项目不需要迁移数据库。关闭程序，更新 `python-version` 源码（本次业务修复文件为 `src/experiment_planner/engine/ax_bridge.py`），重新运行 `main.py`，打开原 `.sqlite` 项目后重新生成下一批即可；原实验编号、实测值和批次历史保留。
